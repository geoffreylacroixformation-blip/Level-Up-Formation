\# INDEX — Documentation de référence Level Up Formation



\## 1. Objet



Ce répertoire contient la documentation de référence officielle du projet Level Up Formation.



Ces documents constituent la source de vérité concernant l'identité visuelle, l'architecture fonctionnelle et technique, la base de données, les technologies utilisées et les ressources graphiques du site.



Avant toute tâche de développement, de modification, de conception ou d'analyse, consulter les documents pertinents de ce répertoire.



Ne jamais se baser uniquement sur l'historique d'une conversation ou sur des suppositions.



\---



\## 2. Organisation de la documentation



\### Brand Book



Contient les règles de l'identité visuelle de Level Up Formation.



À consulter obligatoirement avant toute intervention concernant :



\- Le design du site

\- Les couleurs

\- Les typographies

\- L'identité graphique

\- L'apparence des composants

\- La cohérence visuelle des pages



Le Brand Book constitue la référence prioritaire en matière d'identité visuelle.



\### Structure de la base de données



Contient la structure de la base de données du projet.



À consulter obligatoirement avant toute intervention concernant :



\- Les tables

\- Les colonnes

\- Les relations

\- Les données

\- Les requêtes

\- Supabase

\- L'authentification

\- Les évolutions de la base de données



Ne jamais inventer une structure ou supposer l'existence d'une table, d'une colonne ou d'une relation sans vérification.



\### Répertoire Logos



Contient les logos et les ressources graphiques de Level Up Formation.



Utiliser prioritairement les ressources existantes plutôt que de recréer, modifier ou substituer arbitrairement les éléments graphiques.



Ne pas déformer les logos ni modifier leur identité visuelle sans autorisation.



\### Répertoire MD



Contient les documents Markdown décrivant l'architecture fonctionnelle et technique du site.



À consulter en fonction de la tâche pour comprendre :



\- L'organisation du site

\- Les fonctionnalités

\- Les parcours utilisateurs

\- Le fonctionnement des différentes sections

\- L'architecture technique

\- Les règles de fonctionnement existantes



Ces documents doivent être consultés avant toute modification structurelle ou fonctionnelle.



\### Document Stack Level Up



Contient les informations concernant la stack technique de Level Up Formation.



À consulter obligatoirement avant :



\- L'installation de dépendances

\- Le choix d'une technologie

\- La modification de la configuration

\- L'évolution de l'architecture technique

\- Le développement d'une nouvelle fonctionnalité



Ne pas introduire de technologie supplémentaire sans vérifier sa compatibilité avec la stack existante.



\---



\## 3. Règles de consultation



Avant de commencer une tâche :



1\. Identifier la nature de la tâche.

2\. Consulter les documents de référence correspondants.

3\. Examiner le code existant afin de vérifier que la documentation correspond à l'implémentation actuelle.

4\. En cas de contradiction entre la documentation et le code, signaler cette contradiction avant de prendre une décision importante.

5\. Ne pas modifier les documents de référence sans demande explicite.



Il n'est pas nécessaire de lire l'intégralité de la documentation à chaque session. Consulter en priorité les documents directement liés à la tâche, puis les autres si nécessaire.



\---



\## 4. Priorité des sources



En cas de divergence, appliquer l'ordre de priorité suivant :



1\. Instructions explicites données par le propriétaire du projet.

2\. Documents de référence présents dans ce répertoire.

3\. Code et configuration actuellement présents dans le repository, pour constater l'état réel de l'implémentation.

4\. Décisions documentées précédemment.

5\. Historique des conversations.

6\. Hypothèses de l'agent.



Toute contradiction significative entre les sources doit être signalée. Ne pas arbitrer silencieusement une contradiction susceptible d'affecter le projet.



\---



\## 5. Gestion des ressources et informations sensibles



\- Ne pas supprimer les ressources graphiques existantes sans autorisation.

\- Ne pas exposer d'identifiants, tokens, clés API ou secrets.

\- Ne pas intégrer de secrets dans le code source, la documentation ou Git.

\- Ne pas modifier arbitrairement la stack, l'architecture ou la base de données.

\- Vérifier les ressources existantes avant d'en créer de nouvelles.



\---



\## 6. Objectif



L'objectif de cette documentation est de garantir la continuité du travail sur Level Up Formation entre les différentes sessions de Hermes Agent.



Chaque session doit pouvoir retrouver rapidement le contexte nécessaire, comprendre les choix existants et poursuivre le développement sans repartir de zéro ni remettre en cause inutilement les travaux précédents.
